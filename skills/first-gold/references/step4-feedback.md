# 第 4 步：反馈迭代

目标：知道有多少人在用、他们为什么用或不用，然后每周改一次，直到有人愿意为它付钱。

## 4a. 加访问统计（只看汇总数据）

在产品页面里加一个访问统计，大概了解 DAU、MAU 和留存。

可选的工具（选一个就行）：

- **不蒜子**：在页面里加一段代码，就能显示 PV / UV，最简单
- **Umami**：开源，可以自己部署，有更完整的看板
- **Vercel Analytics**：产品部署在 Vercel 上时，后台一键打开
- **百度统计**：用户主要在国内时可以选

隐私提醒：只看汇总数据，不要记录访客的原始 IP、设备信息等个人信息，也不要把这些数据公开。

几个指标怎么理解：

| 指标 | 含义 | 怎么用 |
|---|---|---|
| PV / UV | 页面浏览次数 / 独立访客数 | 看宣发有没有带来人 |
| DAU / MAU | 每天 / 每月用过的人数 | 看有没有人持续在用 |
| 留存 | 第一天来的人，几天后还有多少回来 | 最重要：留存低，说明还没解决真问题 |

每周在 `04-反馈.md` 里记一次数字。

## 4b. 用户访谈：10 个，每个 30 分钟

发现有朋友在用，就约他聊。数据告诉你“发生了什么”，访谈告诉你“为什么”。

**找谁**：群里活跃的人、用过又不用了的人、你最想服务的那类人。

**30 分钟提纲**：

| 时间 | 聊什么 | 例句 |
|---|---|---|
| 0–3 分钟 | 开场 | “今天想听听你真实的使用感受，说不好用也完全没关系。” |
| 3–13 分钟 | 使用过程 | “你上一次用是什么时候？当时在做什么？能从头讲一遍吗？” |
| 13–23 分钟 | 痛点和替代方案 | “没有这个工具的时候你怎么解决？哪一步最烦？” |
| 23–28 分钟 | 付费意愿 | “如果它要收费，多少钱以内你会愿意试？为什么？” |
| 28–30 分钟 | 收尾 | “还有谁可能也需要这个？方便帮我介绍一下吗？” |

**访谈原则**：多问“上一次发生了什么”，少问“你会不会用”；不推销、不辩解；记录原话。

**记录模板**（写进 `04-反馈.md`，不写真实姓名）：

```markdown
### 访谈 {编号}：{用户类型，例如“大三，想转产品”}（日期）
- 怎么用的：
- 最喜欢的地方：
- 最卡的地方（原话）：
- 愿不愿意付费 / 多少钱：
- 我要改的：
```

## 4c. 每周迭代一次

每周固定一天，把这一周的问题整理一遍：

```markdown
### 第 {N} 周（日期）
- 本周数据：UV ___，留存 ___，新增访谈 ___ 个
- 发现的问题（按严重程度排序）：
  1.
- 这周改了什么：
- 改完的效果：
- 下周要验证什么：
```

一定要迭代起来：不改，就永远不知道哪个改动有用。

## 第一桶金

四步都走完后，帮用户迈出收钱这一步：

1. **先问访谈过的用户**：“如果收费 ___ 元，你愿意吗？”第一批付费用户最可能来自他们。
2. **定一个小价格**：先让人愿意试，比如一次性几块到几十块，或者按月订阅。价格之后可以调。
3. **选一个最简单的收款方式**：微信 / 支付宝收款码、付费社群、按次付费的服务，选你现在马上能用的。
4. **收到第一笔钱时**，在 `progress.json` 的 `first_gold` 里写下金额、日期和来源。进度页会点亮 First Gold 徽章。

收款和经营要遵守相关法律法规和平台规则；涉及发票、税务等问题，以当地规定为准。
